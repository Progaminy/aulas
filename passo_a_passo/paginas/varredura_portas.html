🎯 O que é Varredura de Portas e Para que Serve Cada Teste?

Uma porta de rede (0 a 65535) é um ponto de entrada digital em um computador. A **Varredura de Portas (Port Scan)** envia pacotes de teste para descobrir quais portas estão em modo `LISTEN` (ouvindo conexões), quais estão `FILTERED` (bloqueadas por firewall) e quais estão `CLOSED`.
1. Inspecionar todas as portas locais que estão escutando (LISTEN) no próprio PC:
sudo ss -tulpn
Finalidade: Saber exatamente quais programas locais abriram portas no seu computador.
2. Varredura rápida de portas TCP ativas em uma rede local inteira (ex: 192.168.1.0/24):
nmap -sn 192.168.1.0/24
Finalidade: Mapear quais dispositivos estão ligados e com resposta na rede.

⚡ Todos os Tipos de Varredura de Portas (Sem Exceção)

Cada tipo de varredura possui uma finalidade técnica específica (velocidade, discrição ou profundidade de auditoria):
1. TCP SYN Scan (-sS / Stealth Scan - Exige root):
sudo nmap -sS -p 1-65535 192.168.1.100
Para que serve: Envia um pacote SYN. Não completa o handshake de 3 vias (mais rápido e discreto). Varre todas as 65.535 portas sem exceção!
2. TCP Connect Scan (-sT - Sem necessidade de root):
nmap -sT -p 1-1000 192.168.1.100
Para que serve: Completa a conexão TCP de 3 vias inteira. Usado quando o usuário não possui privilégios de administrador.
3. UDP Scan (-sU - Descobrir serviços sem conexão):
sudo nmap -sU -p 53,67,68,123,161 192.168.1.100
Para que serve: Testa serviços UDP como DNS (53), DHCP (67/68), NTP (123) e SNMP (161).
4. Detecção de Versão de Serviço & Sistema Operativo (-sV -O):
sudo nmap -sV -O -p 22,80,443,8080 192.168.1.100
Para que serve: Identifica o software exato (ex: Apache 2.4.52 ou OpenSSH 8.9p1) e a versão do Kernel do sistema alvo.
PASSO A PASSO 3

🧪 Como Isolar uma por uma Cada Porta para Testes Únicos

Quando uma varredura geral encontra portas abertas, precisamos **isolar porta a porta** para confirmar a conectividade sem ruído de rede:
1. Testar Isoladamente a Porta 22 (SSH) com Netcat (nc):
nc -zv -w 5 192.168.1.100 22
Para que serve: Confirma se o serviço SSH responde no IP alvo sem enviar payload de dados.
2. Testar Isoladamente a Porta 80 / 443 (Web HTTP/HTTPS) com Curl:
curl -I --connect-timeout 5 https://192.168.1.100:443
Para que serve: Requisita apenas o cabeçalho HTTP para validar se o servidor web está ativo.
3. Testar Isoladamente a Porta 53 (DNS) com Dig:
dig @192.168.1.100 google.com +time=3
Para que serve: Testa se o servidor no IP alvo está respondendo requisições DNS ativas.
4. Testar Isoladamente qualquer porta via Socket NATIVO do Bash (/dev/tcp):
(echo > /dev/tcp/192.168.1.100/8080) 2>/dev/null && echo "Porta 8080 ABERTA" || echo "Porta FECHADA"
Para que serve: Teste ultra-rápido sem depender do Nmap ou Netcat instalados no sistema!

📋 Resumo: Tipo de Teste & Sua Finalidade Prática

Tabela explicativa para consulta rápida da utilidade de cada comando:
📌 Tabela de Utilidade Técnica:
• ss -tulpn $\rightarrow$ Diagnóstico Local (Quais processos escutam no próprio computador).
• nmap -sS $\rightarrow$ Auditoria Stealth (Varredura rápida sem completar handshake).
• nmap -sV $\rightarrow$ Identificação de Software (Descobrir versão exata de Apache/SSH/MySQL).
• nc -zv IP PORTA $\rightarrow$ Isolamento Individual (Confirmar se uma porta específica responde).
• /dev/tcp/IP/PORTA $\rightarrow$ Teste Nativo Bash (Funciona em qualquer terminal Linux básico).
