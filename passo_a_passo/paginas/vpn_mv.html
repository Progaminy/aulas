Procedimento Sequencial Definitivo: Limpeza de Lab, Serviço WARP, Teste de Megas & Script Automatizado

ETAPA 1

🧹 Limpar o Laboratório Experimental

Desativar o encaminhamento IP, remover o namespace isolado `laboratorio-vpn` e fechar portas desnecessárias:
1. Confirmar que o encaminhamento IP continua desligado:
sudo sysctl -w net.ipv4.ip_forward=0
2. Remover o ambiente isolado e a interface veth:
sudo ip netns del laboratorio-vpn 2>/dev/null; sudo ip link del veth-host 2>/dev/null
3. Verificar se os proxies 1080/1081 ainda estão ativos:
sudo ss -ltnp | grep -E ':1080|:1081'
4. Encerrar o servidor SSH do laboratório (porta 22):
sudo systemctl disable --now ssh.socket
5. Confirmar fecho da porta 22:
sudo ss -ltnp | grep ':22'
ETAPA 2

⚙️ Garantir o Serviço WARP com o Inicialização do Sistema

Ativar o serviço de fundo `warp-svc` no systemd para inicializar automaticamente com o computador:
1. Ativar e iniciar o daemon warp-svc:
sudo systemctl enable --now warp-svc
2. Confirmar o estado do serviço (Resultado esperado: enabled / active):
systemctl is-enabled warp-svc; systemctl is-active warp-svc
ETAPA 3

🔄 Conectar WARP, Confirmar IP & Reiniciar

Estabelecer a conexão inicial do WARP e validar o túnel antes do reboot:
1. Conectar ao WARP:
warp-cli connect
2. Verificar o estado do túnel:
warp-cli status
3. Confirmar que warp=on no Cloudflare trace:
curl -s https://www.cloudflare.com/cdn-cgi/trace | grep '^warp='
4. Confirmar o novo IP público do túnel:
curl -4 https://icanhazip.com
5. Reiniciar o computador:
sudo reboot
ETAPA 4

🔌 Reconectar Após Cada Arranque do Computador

Após o arranque do computador, verificar o serviço e validar a interface virtual `CloudflareWARP`:
1. Verificar se warp-svc está ativo:
systemctl is-active warp-svc
2. Conectar caso esteja desligado:
warp-cli connect
3. Confirmar estado, trace e interface virtual:
warp-cli status; curl -s https://www.cloudflare.com/cdn-cgi/trace | grep '^warp='; ip addr show CloudflareWARP
ETAPA 5

🔍 Varredura Legal & Lista de Domínios Oficiais

Criar a pasta de monitoramento e a lista de domínios declarados oficialmente gratuitos:
1. Criar a pasta de monitoramento do WARP:
mkdir -p ~/warp-monitor
2. Criar o ficheiro oficiais.txt:
nano ~/warp-monitor/oficiais.txt
3. Ver conexões que o WARP está usando (UDP / TCP):
sudo ss -uapn | grep -E 'warp-svc|warp'
ETAPA 6

📡 O Teste Verdadeiro Quando Estiver Sem Megas

Verificar o comportamento da rede com o modem ligado e sem pacote de dados ativo:
1. Guardar o estado inicial antes do desligamento:
date; warp-cli status; curl -4 https://icanhazip.com
2. Desconectar o WARP temporariamente:
warp-cli disconnect
3. Testar se a Cloudflare é alcançável sem WARP:
curl -4 --connect-timeout 10 --max-time 15 https://www.cloudflare.com/cdn-cgi/trace
4. Reconectar o WARP e verificar o acesso:
warp-cli connect; sleep 5; warp-cli status; curl -s --connect-timeout 15 https://www.cloudflare.com/cdn-cgi/trace | grep -E '^(ip|warp)='
ETAPA 7

📜 Script de Registo Automático (verificar.sh)

Criar o script bash de auditoria completa para registar logs com data e hora:
1. Criar o ficheiro do script verificar.sh:
nano ~/warp-monitor/verificar.sh
2. Tornar o script executável:
chmod +x ~/warp-monitor/verificar.sh
3. Executar a verificação e guardar os logs:
~/warp-monitor/verificar.sh
4. Inspecionar os logs de diagnósticos do WARP:
sudo journalctl -u warp-svc --since '10 minutes ago' --no-pager
5. Gerar pacote completo de diagnóstico da Cloudflare:
sudo warp-diag
ETAPA 8

🛑 Como Desconectar, Desligar ou Matar a VPN WARP

Quando desejar encerrar a VPN e voltar a navegar sem a proteção ou túnel do WARP, utilize estes comandos:
1. Desconectar temporariamente o túnel WARP (Manter o daemon rodando):
warp-cli disconnect
💡 Para que serve: Corta a conexão VPN mantendo o serviço pronto para reconectar a qualquer momento.
2. Confirmar que a VPN foi desligada (esperado: warp=off):
curl -s https://www.cloudflare.com/cdn-cgi/trace | grep '^warp='
💡 Para que serve: Garante que a sua internet voltou a usar o IP direto da sua operadora sem o túnel WARP.
3. PARAR E DESLIGAR COMPLETAMENTE o serviço de fundo do WARP (warp-svc):
sudo systemctl stop warp-svc
💡 Para que serve: Encerra e mata o processo do serviço `warp-svc` no sistema operacional.
4. Desativar a inicialização automática do WARP no arranque do sistema:
sudo systemctl disable warp-svc
💡 Para que serve: Impede que o WARP inicie automaticamente quando você ligar o computador.
